ICONS

Icon set

The product already imports lucide-react, and shadcn's generated components import Lucide internally — so this is really "keep Lucide, or take on a migration." Every option here is MIT-licensed, tree-shaken per-icon, and React-native.

A

Lucide — keep it Recommended

1,500+ icons, one refined outline weight. The default of the shadcn ecosystem and most Figma kits.

  • Zero migration — already wired
  • Matches every shadcn block you'll paste in
  • Consistent 24px grid, 1.5px stroke
  • One weight only — no fill/duotone for emphasis
  • Thin coverage on niche data glyphs (funnel, cohort, pivot)
B

Lucide + Tabler supplement

Keep Lucide everywhere; pull the ~10 data-specific glyphs Lucide lacks from Tabler's 6,000-icon set.

  • Fills the analytics gaps (chart-funnel, chart-dots, table-options)
  • Tabler's stroke matches Lucide closely at 24px
  • Still per-icon imports, no bundle hit
  • Two libraries to keep in your head
  • Slight stroke-cap mismatch if used side by side
C

Phosphor — full switch

1,200+ icons in six weights (thin → fill → duotone). More expressive, more work.

  • Weight range gives real emphasis control
  • Duotone reads well for a marketing home page
  • Re-icon every shadcn component you've added
  • Different visual language than the blocks ecosystem
  • No payoff for a data tool that wants restraint
COMPONENTS

Where prebuilt blocks come from

shadcn/ui is the base — you own the code, no runtime dependency. The question is what you layer on for the parts shadcn doesn't ship: full dashboard blocks, KPI cards, and the marketing pages. All of these are copy-in source, Tailwind + Radix, same as shadcn.

A

shadcn blocks + Tremor Recommended

shadcn official dashboard-01 block for the shell (sidebar + charts + data table). Tremor (Vercel-owned, now fully free) for KPI cards, sparklines, bar-lists, trackers and the funnel.

  • Both are Recharts under the hood — one chart runtime
  • Tremor's "show the data, hide the chrome" matches the product
  • KPI card, spark, funnel, cohort tracker all prebuilt
  • Nothing to license
  • Minor token reconciliation (Tremor uses its own CSS vars)
B

shadcn blocks only

Stay 100% inside shadcn — official charts (11 types incl. KPI) plus dashboard-01. Hand-build the funnel and cohort.

  • Single system, single token set
  • Reference implementation everyone else copies
  • No prebuilt funnel / cohort / bullet — you write them
  • KPI card is barebones vs Tremor's
C

+ Origin UI / Kibo for form polish

Add A, then cherry-pick a few input/combobox/date-range pieces from Origin UI or Kibo UI for the query bar and filters.

  • Nicer multiselect, tag input, date-range than base shadcn
  • Still shadcn-compatible source
  • Third source to track
  • Easy to over-reach — only take 2–3 pieces
Not for this product: Aceternity / Magic UI / Kokonut and the other animation-heavy kits. They're built for marketing splash — beam borders, 3D tilt, scroll parallax. Fine to borrow one hero effect for the home page; keep them out of the app, where motion competes with the data.
THEME

Base neutral, accent, default mode

Your tokens are already the shadcn oklch set with a neutral base. Three sub-decisions: keep or swap the base, add an accent (right now primary is just near-black), and choose whether the app opens dark or light.

A

Neutral base + one indigo accent Recommended

Keep the neutral greys. Introduce a single saturated accent used only for: primary buttons, active nav, links, focus rings, and the emphasized endpoint on charts. Everything else stays greyscale.

  • Accent draws the eye to action and current value, nothing else
  • Greyscale data reads honestly — color means something
  • One hue is easy to keep disciplined across 40 components
  • Needs a semantic scale (good/warn/critical) kept separate from the accent

B

Install a ready-made theme from tweakcn (one CLI line, exports standard shadcn vars). "Vercel" = crisp black/white minimal; "Supabase" = neutral + signature green.

  • Fully-tuned light + dark in minutes
  • Shadows, radius, chart palette all set
  • Reversible — it's just CSS vars
  • "Supabase green" is a borrowed identity
  • Less ownership of the look
C

Keep exactly as-is (neutral, no accent)

Primary stays near-black; no color anywhere.

  • Zero work
  • Very "Linear/Vercel" austere
  • Nothing signals the active tab / primary action
  • Charts have no anchor color — every series competes
  • Reads unfinished for a paid SaaS
Default mode: your screenshots were dark because of defaultTheme="system" + your OS. I recommend committing dark-first (analytics tools are used heads-down; dark reduces chart glare) with a polished light theme and the toggle already in the sidebar. Alternative: default light, which reads friendlier on the marketing home. One call to make.
TYPE

Typeface & number formatting

The app loads Geist today. For a data product the bigger lever isn't the sans — it's whether numbers are set in a tabular face so columns and deltas line up. Right now they aren't.

A

Geist Sans for UI · Geist Mono for every metric Recommended

Keep Geist Sans for all interface text. Set every KPI value, table figure, axis label, delta and record-ID in Geist Mono (or Geist Sans with font-variant-numeric: tabular-nums). One superfamily, two roles.

  • Numbers align vertically — scannable at a glance
  • Mono signals "this is data", matches the IR / dev-tool identity
  • Already loaded; Geist Mono is one more next/font line
  • Mono is wider — tight KPI cards need a size check
B

Inter + Inter tabular figures

Swap to Inter — the most-used dashboard face, high x-height, slashed-zero option, ships tabular figures.

  • Battle-tested for dense data UI
  • Proportional text + tabular digits in one face
  • Loses the Geist / Vercel identity you already have
  • Ubiquitous — reads generic
C

IBM Plex Sans + Plex Mono

A more technical, slightly institutional pairing (what this dossier is set in).

  • Strong sans/mono superfamily, great tabular figures
  • Distinct from the Geist/Inter default
  • Full font swap across the app
  • Heavier personality than the product needs

CHARTS

Charting library

You already depend on recharts, and the eval/answer payload is already "chart-ready". This is mostly about confirming, not switching.

A

Recharts + shadcn Chart wrapper Recommended

shadcn's ChartContainer / ChartTooltip theming layer over Recharts. Tremor's charts (also Recharts) for spark + bar-list + funnel.

  • Already installed — no new dep
  • Themed by your CSS vars automatically
  • Covers area/bar/line/pie/radar + the KPI card
  • SSR-friendly, ~100kb, fine for this data scale
  • Not built for 100k-point series (irrelevant here — you aggregate server-side)
B

Tremor charts as the primary

Lead with Tremor's chart components directly rather than raw Recharts.

  • Least code — prestyled, sensible defaults
  • Bar-list, tracker, funnel-ish out of the box
  • Less control when a view needs something custom
  • Two charting APIs if you also use shadcn charts
C

visx or ECharts

Low-level (visx/D3) or heavyweight (ECharts) for bespoke or very large visualizations.

  • visx: total control for a signature viz
  • ECharts: handles huge datasets, 3D, maps
  • Real engineering time / bundle weight
  • Overkill for aggregated hiring metrics

HOME

Landing page

Current / is a plain text list of features. 67% of top SaaS sites now lead with a real product screenshot in the hero and a single CTA. Three formats:

A

Product-forward hero + bento Recommended

Hero = one confident headline, one sub-line, one CTA ("Create a workspace"), and a real screenshot of the app answering "How many people are active in Engineering?" with the grounded answer + chart visible. Below: a 4-tile bento of the differentiators, then a 3-step "how it works", then a closing CTA band.

  • Shows the product in 2 seconds — the answer is the pitch
  • Bento tiles carry: Ask don't build · Grounded · Role-scoped · IR boundary
  • Single CTA converts better than a menu of them
  • Needs one polished screenshot (or a static mock of the answer card)
B

Minimal dev-tool

Headline + sub + CTA, then an animated "terminal" that types a question and reveals the JSON IR then the answer. Very Linear/Vercel.

  • Signals "for people who think in queries"
  • The IR reveal is genuinely the interesting bit
  • Less legible to a CHRO buyer than a real answer card
  • More build (the typing sequence)
C

Keep current, just styled

Same content, given the new theme/type and a proper hero block.

  • Fastest
  • Enough if the home page isn't a priority yet
  • Still text-only — no product shown
  • Doesn't feel like a 2026 SaaS

LOGIN

Login & signup

Both patterns are current in 2026. For a product with a strong "what you get" story (instant seeded dataset, 5 roles), the split screen earns its space.

A

Split screen — form left, value panel right Recommended

Left: the form only (email, password, submit, switch-to-signup). Right: a fixed panel — one line of positioning, three value bullets, the five roles as chips, and on signup the line "We'll generate a demo hiring dataset for {org} the moment you land."

  • Reassures during the highest-friction moment
  • Right panel explains the seeded-data magic before they see it
  • Role chips preview the RBAC story
  • Right panel hidden on mobile (form-only there — fine)
B

Centered card, minimal

Single centered card, wordmark above, form, one helper link. Nothing else.

  • Zero distraction, fastest to build
  • Feels crisp and confident
  • Wastes the signup moment — no story told
C

B, plus a single quote or metric under the card.

  • A little warmth without a full panel
  • You don't have real testimonials yet — would be filler

PLAN

Suggested build order

Tokens — theme, type, icons

Commit the accent + dark-first decision into globals.css. Add Geist Mono, wire tabular-nums into a <Metric> primitive. Pull the handful of Tabler glyphs. No layout change — everything just looks decided.

Primitives — KPI card + Chart wrapper

Build <StatCard> (variants A/B/C) and adopt the shadcn Chart wrapper + Tremor spark/bar-list. Replace the current inline answer chart with the themed version.

Dashboard tab + first 5 MODELS views

Top bar + tab strip. Dashboard = KPI row (C) + headcount-by-band, trend, funnel, time-to-fill dist, composition. All from existing metrics.

Explore tab + remaining MODELS

Dimension picker → matching view + data table. Add cohort, bullet, aging-threshold, source overlay (one new executor aggregation each).

Home + login

Rebuild / as option A and /login + /signup as split screen. Reuses every primitive from P1–P2.
